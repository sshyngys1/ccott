## 1. Название и суть

**Meniscus** — визуальный язык island-win. Мениск — изогнутая поверхность жидкости у стенки сосуда: тонкая светлая кромка, под ней толща. Отсюда три опоры:

1. **Кромка, а не рамка.** Форму задаёт 1px specular-кромка (светлая сверху, гаснет к бокам, слабый отблеск снизу), а не сплошная обводка.
2. **Толща, а не матовость.** Стекло — это тонировка поверх настоящего размытия рабочего стола (нативный Acrylic). Без него — плотная подложка, без «грязной» полупрозрачности.
3. **Капля, а не окно.** Остров — одна капля, которая растекается из пилюли вниз (упругая пружина) и стягивается обратно (без отскока).

Айдентика (отличия от Apple и платного Island): бирюзовый акцент «meniscus teal» (`#3dd6c6` / `#0a7369`), собственные иконки на 20px-сетке, пилюля-«вырез» чёрная в **обеих** темах, блик кромки, который «ловит» курсор, капля-тост через gooey-фильтр. Никаких ассетов, названий и иконок оригинала.

## 2. Принципы

- **Одна поверхность.** Пилюля и панель — один и тот же элемент `.ig-glass`, меняются только размеры, радиус и модификатор `--pill`. Никаких «окон в окне».
- **Тихо в покое.** Свёрнутый idle — ноль анимаций, ноль rAF, ноль фильтров (цель 0 % CPU). Двигается только то, что отражает живое состояние (эквалайзер при игре).
- **Концентричность.** Внутренний радиус = внешний − отступ: панель 32 − 16 = карточки 16; карточка 16 − 4 = контролы 12.
- **Читаемость важнее прозрачности.** Альфы поверхностей подобраны так, что основной и вторичный текст проходят WCAG AA даже над белым рабочим столом (§10, проверяется тестом).
- **Токены — единственный источник.** Модули используют только `var(--ig-*)` и классы `.ig-*`.

```
┌────────────────────────────────────────────────────────────┐ y=0
│                 ┌──────── pill 224×36 ────────┐             │ y=8  (--ig-pill-top)

│                 ≤ 64px тени вниз                             │

```

- Остров привязан к **верхнему центру**: `left = (800 − w) / 2`, `top = --ig-pill-top`.
- Тень `--ig-shadow` (худший слой `0 28px 56px -20px`) уходит на 36px вбок, 64px вниз, 8px вверх → влезает (проверяет `geometry.test.ts`).
- Перелёт пружины раскрытия по ширине: 720 → 747px (+27). Хвост тени на это время (~150 мс) срезается краем окна на ≤ 10px при прозрачности < 10 % — незаметно.

## 5. Пилюля (свёрнутый остров)

Класс: `ig-glass ig-glass--pill`. Внутри модификатора текстовые и акцентные токены **переназначены** на светлые (`--ig-text-on-strong`, `--ig-accent-on-strong`), поэтому контент пилюли одинаково светлый в обеих темах — модулям ничего делать не нужно.

| Состояние | Размер | Содержимое (слева → справа) | Отступы |
|---|---|---|---|
| **idle** (покой) | 224×36, r 18 | время `14:32` (md, semibold, tabular) · · · облако 16px + `12°` (secondary) | 16px слева, 14px справа |
| **activity** (медиа/таймер) | 304×36 | мини-обложка 24×24 r 6 · название (sm, secondary, truncate) · эквалайзер `.ig-eq` (4 полосы 3×14, accent) | 6px слева (обложка концентрична: 18 − 6 = 12 ≈ r 6 + зазор), 14px справа |
| **toast «Скопировано»** | 312×36, держится `durations.toastHold` = 1.6 с | бейдж 24px `--ig-success` с галочкой · «Скопировано» (sm, semibold) · превью (xs, tertiary, truncate) | 6 / 14px |
| **hover** | базовый размер + 12px ширины, +2px высоты (`hoveredPill()`), r = h/2 | как в базовом состоянии; фон светлеет на 6 %, кромка ярче (`[data-hover="true"]` или `:hover`) | — |

### 6.3 Общие правила вкладок волны 2

- Контент вкладки — 688 × 312, ничего не скроллится, кроме явно помеченных списков (`.ig-scroll`). Скролл всей панели запрещён.
- Внутри карточки (`.ig-glass-card`, r 16) — отступ 4px, ряды/поля r 12 (концентрично); внутри поля (`.ig-field`, r 12) — бары с отступом 4–6px и кнопками `--sm` r 8.
- Плотные кнопки — `.ig-glass-control--sm` (28px, текст xs). Деструктивные — `--danger` (нейтральны в покое, красные под курсором).
- Цветной **текст** (ссылки, ошибки, «Сохранено», статус) — только `--ig-accent-text` / `--ig-danger-text` / `--ig-success-text` / `--ig-warning-text`; `--ig-accent`/`--ig-danger`/… — для заливок, колец, иконок. Причина — §10: в `acrylic` над белым/чёрным столом чистый акцент не держит 4.5:1, «-text»-токены подобраны по режимам.
- Списки: строки без подложки, hover — `--ig-surface-hover`, клавиатурный курсор (`aria-selected`) — `--ig-row-selected` + 1px акцентная линия, открытый элемент (`aria-current`) — нейтральная плашка `--ig-row-current`.
- Пустое состояние любой области — `.ig-empty` (круг 48 с иконкой 22, заголовок sm/600, текст xs tertiary ≤ 300px, опционально кнопка `--sm`).
- Появление/удаление строк — `listItem` + `springs.list` из `motion.ts`, перестановка — `layout="position"` на строке. Никакого `backdrop-filter` в строках.

- **Строка** (`li.ig-list-row`, `role="option"`): ведущий бейдж 32×32 r 8 `.ig-list-row__lead` с иконкой по `kind` (`text` → `IconText`, `link` → `IconLink` + `data-kind="link"` (акцентный), `files` → `IconFile`); заголовок — `preview` в одну строку (sm, у `link` — `--ig-accent-text`); мета xs tertiary — «{приложение} · {относительное время}» (`sourceApp` без `.exe`, «Проводник» для explorer; «только что / N мин назад / N ч назад / вчера / N дня назад / 12 окт»), для `files` префикс «N файла ·», для картинок «Изображение W×H ·».
- **Картинка:** `.ig-list-row--media` (64px), вместо бейджа — `<img class="ig-thumb">` 72×48 r 8 (`preview` — data: URL), заголовок «Снимок экрана» (или «Изображение»).
- **Действия** (`.ig-list-row__actions`, справа): «Закрепить» (`IconPin`, `aria-pressed={pinned}`) и «Удалить» (`IconTrash`, `--danger`) — `--icon --ghost --sm`. Видны на hover, на клавиатурном курсоре и при фокусе внутри строки; у закреплённой записи кнопка-булавка видна всегда (акцентная) — это и есть метка «закреплено». Клик по кнопкам не должен вставлять запись (`stopPropagation`).
- **Порядок:** секция «Закреплённые» (с `IconPin` 12 в подписи) — первой, потом «Недавние». Секцию без записей не показывать (при поиске — тоже).
- **Клавиатура:** `↑/↓` двигают `aria-selected` (курсор, начиная с первой записи), прокрутка следует за курсором (`scrollIntoView({block:"nearest"})`); `Enter` / клик — `clipboard_paste({mode:"paste"})` (UI сначала сворачивает остров, §3a); `Shift+Enter` / `Shift+клик` — `mode:"copy"` и тост «Скопировано» без вставки; `Del` — удалить; `Ctrl+P` — закрепить/открепить. Подсказка — строка `.ig-kbd` внизу (xs tertiary, 18px); в `title` строки — «Клик — вставить · Shift+клик — только скопировать».
- **Размеры:** список 246px = ≈ 4.5 строки по 48 (+ подписи секций) — пятая строка всегда «подрезана» маской, это намеренная подсказка, что есть ещё. Скролл — `.ig-scroll .ig-scroll-fade` + `useScrollFade(ref)`: край гаснет на 20px только там, куда можно прокрутить (`data-at-start/end`). Скроллбар 6px, `--ig-stroke-strong`.
- **«Очистить»:** `.ig-glass-control--danger` с `IconTrash` → `clipboard_clear({keepPinned:true})`. Без подтверждения (закреплённые остаются, это написано в пустом состоянии); `disabled`, если записей нет.
- **Пусто:** `.ig-empty` с `IconClipboard` — «История буфера пуста» / «Скопируйте текст, ссылку, картинку или файлы — запись появится здесь. Закреплённые записи не удаляются при очистке.» **Не найдено:** `IconSearch` — «Ничего не найдено» / «По запросу «…» записей нет…» + кнопка `--sm` «Сбросить поиск».
- Новая запись (`clipboard://added`) въезжает сверху `listItem.initial → animate`, курсор не прыгает.

### 6.9 Фокус полей (`wave2-focus-{dark,light}.png`)

- Окно получает клавиатуру только пока фокус в поле (контракты §3a), поэтому «где я печатаю» должно читаться мгновенно. Единый рецепт — токен `--ig-focus-ring` = `inset 0 0 0 1px var(--ig-accent-text), 0 0 0 3px var(--ig-focus-halo)`: линия гарантирует ≥ 3:1 к фону в любой теме/подложке (тест), ореол даёт заметность.
- Где: `.ig-glass-input` на **любом** фокусе (и мышью — `:focus`, не только `:focus-visible`); `.ig-field:focus-within` (textarea/редактор внутри — сами без рамки); одиночный `.ig-editor` вне поля; `.ig-select > select:focus-visible`. Ошибка — `aria-invalid="true"` на input / `data-invalid="true"` на `.ig-field`: линия `--ig-danger-text` + ореол `--ig-danger-soft`.
- Кнопки, чипы, переключатели, ряды — прежний `:focus-visible` outline 2px `--ig-focus` (только с клавиатуры). Ряд списка — inset-outline (чтобы не вылезал за карточку).
- Caret — `--ig-accent`; выделение — `--ig-accent-soft`. Для превью/тестов везде работает `data-focus-visible="true"`.

Волна 2: `springs.view` (k 900, c 54, ζ 0.9 — вид «Настройки» ↔ вкладки, сдвиг `viewSlide` 16 / −12px по x), `springs.list` (k 1100, c 66, ζ ≈ 1 — `layout`-перестановка строк), `listItem` (initial/animate/exit для строк: появление `y −6 → 0`, удаление — opacity + `height → 0` за 120 мс).

Также `durations` (instant .06 · fast .10 · med .16 · slow .26 · toastHold 1.6 с), `layerScale` (панель въезжает с `.96`, уходит к `.98`), `tabSlide` (слайд контента вкладки 6 / −4px), `easings` (`out`, `inOut`, `in`), утилиты `dampingRatio()`, `overshoot()`. Значения проверены настоящим решателем Motion (`springTrace.test.ts`, `motion.test.ts`).

**Контент анимируется только `opacity` и `transform`.** `filter: blur()` на появлении контента убран: это отдельный GPU-проход на каждый кадр на площади всей панели (в живом окне именно здесь были первые «горбатые» кадры).

**Что анимируется.** Рекомендация — анимировать **реальные** `width/height/borderRadius` контейнера острова (`animate={{ width, height, borderRadius }}`), а не `layout`-трансформацию: при `layout` Motion масштабирует элемент через `scale`, и 1px-кромка, зерно и блик (псевдоэлементы) растягиваются в 3× по ширине и в 11× по высоте посреди анимации. Цена реального ресайза мала: остров `position: absolute`, контент панели лежит в слое фиксированного размера (`width: --ig-panel-width`, `left: 50%; margin-left: -panel/2`, `transform-origin: 50% 0`) и не перекладывается, контейнер — `overflow: hidden`. Если F1 всё же выберет `layout`, то с `layout="size"` и `style={{ borderRadius }}` (Motion корректирует радиус), но кромка будет «плыть».

Порядок при раскрытии: `kind = expand` → форма растёт по `springs.expand`; одновременно пилюльный контент уходит (`fades.pillOut`, 60 мс), панельный приходит `fades.panelIn` (`opacity 0→1`, `scale .96→1`). При сворачивании: контент панели уходит `fades.panelOut`, форма — `springs.collapse`, контент пилюли проявляется с задержкой 40 мс (`fades.pillIn`). Hover-рост пилюли — `springs.pill`.

`MotionConfig reducedMotion="user"` — обязательно в корне. CSS: при `prefers-reduced-motion` эквалайзер статичен, `scale` у кнопок выключен.

## 10. Acrylic против fallback и контраст

**Режимы (`<html data-vibrancy>`)**

| Режим | Что под островом | Как выглядит |
|---|---|---|
| `acrylic` | нативное размытие реального рабочего стола (DWM) под прозрачным окном, обрезанное регионом по форме острова | тонировка 72 % (dark) / 68 % (light) + sheen + кромка + зерно 3.5 %; внешней тени нет (регион её всё равно срежет) |
| `mica` | размытые **обои** (не то, что под окном), DWM сам тонирует их почти до непрозрачности | тонировка 42 % / 45 % |
| `none` | ничего (прозрачное окно, браузер, ошибка vibrancy) | **полностью плотная** подложка (альфа 1) + CSS-стекло (кромка, sheen, glow, зерно), полная тень |

**Плотность панели в `none` (правка после живого окна).** Раньше подложка была `--ig-surface = rgb(22 23 29 / .97)`, и в настоящем окне сквозь тёмную панель читался текст приложения под ней. Причина — сама альфа: окно прозрачное, WebView2 отдаёт DWM пиксель с альфой .97, и 3 % фона подмешиваются как есть. Для светлого текста на тёмной подложке это заметно: измерение по скриншотам (светлый текст под панелью, 239 против 25 в яркости) дало эффективную прозрачность ≈ 4.5 % (подмешивались и градиент sheen, и inner-glow, но не они делают панель «стеклянной»). Слои `.ig-glass` (кромка, зерно, блик, `opacity` у анимаций контента) прозрачности не добавляют: контент панели лежит над подложкой, а `opacity` анимируется у контентного слоя, не у острова. Решение: `--ig-surface` и `--ig-surface-strong` в `none` — альфа **1** (в обеих темах и при `prefers-reduced-transparency`). Кромка, блик, зерно и тень остаются; для `acrylic`/`mica` (полупрозрачные подложки поверх нативного blur) ничего не изменилось.

`backdrop-filter` на панели **не используется** — в окне Tauri он размыл бы только пустоту. Исключения — `.ig-glass--refract` на мелочи и превью-стенд, где нативный blur *симулируется* CSS (`.pv-window--acrylic .pv-island { backdrop-filter: blur(30px) saturate(1.8) }`).

**Контраст (WCAG 2.x, худший реалистичный фон под островом).** Для тёмной темы худший случай — белая вкладка браузера под островом; для светлой — чёрный фон. ## 11. Блик за курсором

## 14. Производительность

- Idle-пилюля: никаких `animation`, `filter`, `backdrop-filter`, rAF. Эквалайзер крутится только при `data-playing="true"` и только `transform`.
- Зерно — растровый SVG-тайл (рисуется один раз), а не живой фильтр.
- Блик — перерисовка фона только при движении курсора над островом.
- `feDisplacementMap` — только на элементах ≤ ~120×120.
- Волна 2: в рядах, чипах, полях нет `backdrop-filter`/`filter`; маска `.ig-scroll-fade` — одна статичная `mask-image` на контейнере (не анимируется); прогресс таймера — `transform`/`stroke-dashoffset` раз в секунду; единственная бесконечная анимация — точка «Сохранение…» (только во время запроса) и эквалайзер при игре.
- Пилюля → панель: анимируются 3 значения одного абсолютно позиционированного элемента; контент панели не перекладывается (фиксированный слой).
- **Остров центрируется в CSS** (`left: 0; right: 0; margin-inline: auto` при явной ширине), а не `x: "-50%"`: `transform` делает остров отдельным композитным слоем, и ресайз такого слоя дороже.
- **`island_set_shape` — несколько вызовов на переход, а не по кадру.** Раньше rAF-цикл слал форму каждый кадр (≈ 25–45 вызовов IPC на одно раскрытие; в Tauri это синхронная команда в главном потоке — том же, где живёт WebView). Теперь: (1) в начале перехода — *покрывающая* форма (объединение текущего и целевого бокса + перелёт пружины + 1px; остров никогда не «проваливается» под курсор при росте и не сжимается под курсором при сворачивании); (2) когда Motion сообщил `onAnimationComplete` — точная конечная форма; (3) точная форма при монтировании и при `resize`. Итого ≈ 2–3 вызова на переход (раньше ≈ 25–45). Нулевая цена в покое сохранена. См. `src/shell/shape.ts`.
- Тяжёлые эффекты стекла перерисовываются на каждом кадре ресайза: исключены `filter: blur()` на контенте, а внешняя тень `--ig-shadow` оставлена трёхслойной только на покое (см. измерения ниже).

### Измерения в живом окне (Tauri 2 / WebView2 155, 2560×1600 @150 %, ≈ 125–165 Гц)

Инструмент: rAF-логгер + `PerformanceObserver` (`longtask`, `long-animation-frame`) через CDP, курсор — `SetCursorPos` на пилюлю; окно — первые 700 мс раскрытия. 3 раунда × 9 раскрытий, «до» и «после» чередовались в одном окне времени.

| | до | после |
|---|---|---|
| вызовов IPC (`island_set_shape` + `island_set_mode`) на раскрытие | ≈ 21–31 | **4** (3 + 1) |
| вызовов IPC на сворачивание | ≈ 40 | **3** |
| кадров за первые 700 мс раскрытия (идеал ≈ 87) | 36–48 | **62–70** |
| p95 интервала между кадрами (раскрытие) | 22.4–23.1 мс | **8.8–15.7 мс** (в двух из трёх прогонов 8.8) |
| «горбатых» кадров 20–100 мс на раскрытие | ≈ 1.8 | **≈ 0.6** |
| зависаний кадра > 100 мс, из 27 раскрытий | 20 (≈ 280 мс на раскрытие) | 12 (≈ 140 мс на раскрытие) |
| сворачивание: p95 кадра | 8.3–8.5 мс | 8.4–8.5 мс (было гладко и раньше) |

В обычном браузере (мок-IPC, `npx vite --port 1440`, Edge headless, программный рендер) измерено то же: перелёт до 746px, вход в 2px от 720 примерно за 240 мс после начала движения; сворачивание в 2px ≈ 200 мс.

**Причины подлагивания.**
1. *Стоимость кадра* (исправлено). В трассе (`Tracing`) GPU-растр одного кадра раскрытия занимал 5–11 мс при бюджете ≈ 6 мс (165 Гц), первый кадр — ≈ 49 мс; main-thread был свободен (long tasks = 0, `blockingDuration` = 0), так что узкое место — растеризация и IPC, а не JS. Вклад по результатам A/B с CSS-переопределениями на живом окне: (а) третий слой внешней тени (blur 56px) — самый тяжёлый одиночный элемент: без внешней тени «горбатые» кадры исчезали (30 → 0–4 на выборку), с двумя слоями p95 кадра 15 → 8.7 мс; (б) по-кадровый IPC `island_set_shape` (25–45 синхронных команд в главном потоке на раскрытие) — убран; (в) в программном/BitBlt-режиме (`--disable-direct-composition`) самым дорогим оказалась кромка `::before` (mask-composite: без неё 83 → 8 «горбатых» кадров). Дополнительно убраны `filter: blur()` на появлении контента и `translateX(-50%)` на анимируемом контейнере — по отдельности они заметного вклада в измерениях не дали, убраны как гигиена (лишний GPU-проход и композитный слой на площади всей панели).
2. *Зависание первого кадра на 300–450 мс* (**не лечится из фронтенда**): GPU-процесс WebView2 блокируется внутри `DXGISwapChainImageBacking::Present` на первом кадре перехода после ≥ ~1 с простоя (ширина острова стоит на месте, потом прыгает к 734; в трассе `Present` = 290–437 мс, при том что main-thread свободен). Воспроизводится без курсора (событие `island://hover` из самой страницы), с заблокированным IPC, со всеми эффектами стекла, выключенными, и при выключенном `WS_EX_LAYERED`-переключении — значит, это не CSS и не IPC. С флагом WebView2 `--disable-direct-composition` (и с `--disable-gpu`) таких зависаний нет, но в этих режимах кадры дороже (18–36 мс при раскрытии). Частота зависаний нестабильна (0–9 из 9 раскрытий от прогона к прогону). Предложения для Rust-стороны — в отчёте агента.

## 16. Требования к R1 (нативное окно)

- **Регион:** `SetWindowRgn(CreateRoundRectRgn(x, y, x+w+1, y+h+1, 2r, 2r))` по `IslandShape`, **в физических px** (умножить на `scaleFactor`), эллипс = `2·radius`. Обновлять на каждый `island_set_shape` (≤ 1/кадр).
- Регион без сглаживания → «лесенка» на скруглениях. Её прикрывают `--ig-edge-shade` (волосяная тёмная линия) и кромка; радиусы 18/32 при 100–150 % DPI дают ступеньки ≤ 1px. Если заметно — предложение: регион на 1px **меньше** формы по контуру (UI это не требует менять).
- **Тень** при регионе не видна (всё вне формы обрезано), поэтому в `acrylic/mica` `--ig-shadow: none`. Если R1 обойдётся без региона (blur только под формой иным способом) — сообщить, вернём тень.
- **Acrylic:** `apply_acrylic(window, Some((16, 16, 20, 0)))` — тонировку делает CSS (альфа 0 или минимальная), иначе контраст станет непредсказуемым. **Mica:** `apply_mica(window, Some(theme == dark))` — тема Mica должна совпадать с `data-theme`.

## 17. Открытые вопросы и риски

1. **Неактивное окно и системные backdrop'ы.** Окно `WS_EX_NOACTIVATE` никогда не активно. DWM system backdrop (Mica, а на новых Windows 11 и Acrylic через `DWMWA_SYSTEMBACKDROP_TYPE`) у неактивных окон заменяется сплошным цветом. Старый путь Acrylic (`SetWindowCompositionAttribute`, Windows 10 / 11 21H2) от активности не зависит, но известен лагами при перемещении/ресайзе. R1 должен проверить, что именно вызывает `window-vibrancy` на целевых сборках, и при сплошной заливке возвращать `applied: "none"` — тогда включится плотный fallback.
2. **«Лесенка» региона** на скруглениях (см. §16) — проверить на 125/150 % DPI.
3. **Перелёт ширины** при раскрытии срезает хвост тени краем окна на ≤ 10px (только `none`).
4. **`backdrop-filter: url()`** (`--refract`) — Chromium-only; в WebView2 работает, в Firefox — нет (неважно).
5. Тёмная тема поверх белых окон в acrylic выглядит серой — предлагается «авто»-тема по яркости фона (волна 2).
6. Шрифт: Segoe UI Variable есть в Windows 11; в Windows 10 фолбэк на Segoe UI (метрики чуть шире — подписи плиток «Текст с экрана», «Запись экрана» стоит проверить на Windows 10).
