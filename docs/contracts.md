# Контракты island-win

Единый источник правды для всех агентов. Типы в коде — `src/shared/types.ts` (TS) — **приоритетнее** этого текста при расхождении.
Владелец: Orchestrator. Нужна правка контракта → опиши её в отчёте, Orchestrator решит и обновит оба файла.

## 1. Общие соглашения IPC

- Команды Tauri: `snake_case`, префикс домена — `island_*`, `window_*`, `settings_*`, `updater_*`, `media_*`, `audio_*`, `clipboard_*`, `notes_*`.
- Аргументы с JS передаются в camelCase (`{ positionMs }`), в Rust параметр `position_ms` — Tauri конвертирует сам.
- Структуры Rust: `#[derive(Serialize, Deserialize, Clone)] #[serde(rename_all = "camelCase")]`. Enum-ы — `#[serde(rename_all = "camelCase")]` (→ `"playPause"`, `"acrylic"`).
- Ошибки команд: `Result<T, String>` (сообщение для лога/тоста; UI не парсит текст).
- События: `домен://событие`, payload — тип из `Events` в `types.ts`. Эмитятся через `app.emit(...)` (всем окнам).
- Время — epoch ms (`i64` в Rust, `number` в TS). Картинки в IPC — `data:` URL.
- Команды не блокируют UI-поток: тяжёлое — в `tauri::async_runtime::spawn_blocking` / отдельный поток.
- UI вызывает Rust **только** через `src/ipc` (типизированные `invoke<C>()` / `listen<E>()`); прямой `@tauri-apps/api/core` в модулях запрещён.

## 2. Окно острова (волна 1, R1)

- Одно окно, label **`island`**: без рамки, прозрачное, always-on-top, `skipTaskbar`, без тени, нересайзится. Размер фиксирован: `ISLAND_WINDOW = 800×520` CSS px. Позиция: по центру верхнего края выбранного монитора, `y = 0`.
- Win32-стили: `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` (не крадёт фокус, нет в Alt+Tab). Окно создаётся видимым (`visible: true`): у скрытого при создании окна WebView2 не регистрирует приём перетаскивания файлов на своих дочерних окнах, и drop в док не работает. Прозрачное окно до позиционирования невидимо.
- Видимая форма острова — React-элемент внутри окна. UI сообщает её через `island_set_shape({ shape })` при каждом изменении (во время анимации — не чаще 1 раза за кадр, rAF-троттлинг на стороне UI).
- Rust опрашивает курсор (`GetCursorPos`, ~60 Гц, только пока окно видимо), сравнивает с `IslandShape`:
  - курсор вне формы → `set_ignore_cursor_events(true)` (клики проходят сквозь);
  - внутри → `set_ignore_cursor_events(false)`;
  - при смене состояния эмитит `island://hover { inside }`.
- `island_set_mode({ mode })` — UI сообщает collapsed/expanded (Rust может использовать для частоты опроса и регионов).
- `window_set_vibrancy({ mode })` → `VibrancyResult`: пробует Acrylic/Mica (`window-vibrancy`), при ошибке возвращает `applied: "none"` и текст ошибки. Если blur применяется ко всему окну, R1 ограничивает его формой (`SetWindowRgn` по `IslandShape`) — результат и артефакты описать в отчёте.
- `window_list_monitors()` → `MonitorInfo[]`.

## 3a. Клавиатурный фокус (волна 2, решение пользователя)

Окно `WS_EX_NOACTIVATE` не получает клавиш. Механизм:
- **F1 (глобально, модулям ничего делать не нужно):** document-level `focusin` на `input, textarea, [contenteditable="true"]` внутри раскрытой панели → `island_set_keyboard_focus({ active: true })`. При сворачивании панели или `Escape` → `blur()` активного элемента, `island_set_keyboard_focus({ active: false })` и остров сворачивается (один Escape; модуль, которому Escape нужен для себя — очистить поиск, — вызывает `e.preventDefault()`). На `island://focus-changed { active:false }` — только `blur()` и сброс флага, без повторного вызова команды (фокус уже ушёл к другому приложению). Пока фокус активен, остров не сворачивается по уходу курсора (сворачивается по Escape / клику вне — т.е. потере фокуса).
- **R1:** `active:true` → запомнить `GetForegroundWindow()` (если это не наше окно), временно снять `WS_EX_NOACTIVATE` (через тот же subclass-механизм), `SetForegroundWindow` на остров (с обходом foreground lock: `AttachThreadInput` / `AllowSetForegroundWindow` / ALT-trick — описать выбранное в отчёте). `active:false` → вернуть `NOACTIVATE`, `SetForegroundWindow(запомненное)` если окно ещё живо. `WM_ACTIVATE(WA_INACTIVE)` пока активен фокус → вернуть `NOACTIVATE` и эмитить `island://focus-changed { active:false }`.
- **R2 (`clipboard_paste` mode `paste`):** не зависит от R1 — сам отслеживает последнее foreground-окно **не нашего процесса** (`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`), перед `SendInput(Ctrl+V)` делает его foreground, если сейчас foreground — остров. UI перед вызовом paste сворачивает остров.

## 3b. Live-activities, настройки, DND

- Модуль задаёт `compact` (F2: трек — в `home`, таймер — в `notes`). F1 рендерит в пилюле активность с наибольшим `priority` среди `useIsActive()==true` (ширина — токен activity pill из design-spec), иначе часы.
- Состояние, нужное и вкладке и `compact` (медиа, таймер), F2 держит в своих Zustand-сторах в `src/lib/<area>/` или в модуле; F2 сам вызывает `src/ipc` из модулей.
- Настройки: UI — F1 (`src/shell/settings/**`); с v0.4 — в отдельном окне (§25), открывается шестерёнкой в таб-баре и пунктом трея. `doNotDisturb=true` → F1 не показывает тосты в пилюле. `hideInFullscreen` и `monitor` исполняет R1 целиком на своей стороне.

## 4. Интерфейс UI-модуля

```ts
interface IslandModule {
  id: ModuleId;            // "home" | "clipboard" | "text" | "notes" | ...
  title: string;           // подпись вкладки (ru)
  icon: ComponentType<ModuleIconProps>;
  Tab: ComponentType;      // содержимое раскрытой панели
  compact?: { useIsActive(): boolean; priority: number; View: ComponentType }; // live-activity в пилюле
  order: number;
}
```

- Модуль живёт в `src/modules/<id>/index.ts(x)` и экспортирует `default` объект `IslandModule`.
- `src/modules/registry.ts` (F1) — массив модулей; добавление модуля = одна строка импорта + одна строка в массиве.
- Чистая логика модулей — `src/lib/<area>/*.ts` + `*.test.ts` рядом (vitest).

## 5. Мок-IPC

- `src/ipc/index.ts` экспортирует `invoke<C extends CommandName>(cmd, args): Promise<CommandResult<C>>` и `listen<E extends EventName>(event, cb): Promise<Unlisten>`.
- Если `window.__TAURI_INTERNALS__` нет (обычный браузер, `npm run dev`) — используется `src/ipc/mock.ts` с правдоподобными данными (играющий трек, 10 записей буфера, 3 заметки) и эмуляцией событий. `island://hover` в моке генерируется из `mouseenter/mouseleave` по элементу острова.
- Так UI и дизайн проверяются в браузере (`http://localhost:1420`) без Rust.

Пружины анимаций — `src/design/motion.ts`: `export const springs = { expand, collapse, tab, press }` (объекты transition для Motion).
Панель (`--ig-panel-width/height` + тень) обязана помещаться в `ISLAND_WINDOW` 800×520.

## 7. Shell bus (волна 2)

`src/shared/shellBus.ts`: модули (F2) просят оболочку (F1) без импорта её внутренностей — `requestShell({ type: "collapse" })` (свернуть сразу и отпустить клавиатурный фокус; вызывать перед `clipboard_paste` mode `paste`) и `requestShell({ type: "openTab", tab })` (раскрыть и открыть вкладку; клик по live-activity в пилюле) и `requestShell({ type: "toast", text })` (короткое сообщение в пилюле; при `doNotDisturb` не показывается). F1 подписывается один раз через `onShellRequest` в оболочке. `requestShell` возвращает `Promise<void>`, который резолвится, когда оболочка обработала запрос (для `collapse` — фокус уже отпущен): `await requestShell({type:"collapse"})` перед `clipboard_paste`.

## 8. Вызов горячей клавишей и полноэкранные приложения (v0.1)

- `Settings.summonHotkey` — глобальное сочетание (синтаксис акселератора Tauri, по умолчанию `"Ctrl+Alt+I"`, `""` = выкл). R1 регистрирует его (`tauri-plugin-global-shortcut`); `settings_set` с занятым/некорректным сочетанием возвращает ошибку и оставляет прежнее. По нажатию R1 показывает остров (даже если он скрыт полноэкранным приложением, временно, до сворачивания) и эмитит `island://summoned`; UI раскрывает остров, а если уже раскрыт — сворачивает. После `island_set_mode({mode:"collapsed"})` R1 возвращает скрытие, если полноэкранное приложение всё ещё на экране и оно не в списке.
- `Settings.fullscreenAllowlist` — exe (lower-case), поверх которых остров не скрывается. По умолчанию пусто → в полноэкранных приложениях остров скрыт (`hideInFullscreen=true`).
- `window_recent_fullscreen_apps` — R1 запоминает полноэкранные приложения, которые видел (exe, заголовок, время), хранит до 20 в `fullscreen_seen.json` рядом с `settings.json`. Настройки (F1) показывают этот список с переключателями «показывать остров» → `settings_set({ patch: { fullscreenAllowlist } })`.
- Эксклюзивный полноэкранный режим (D3D exclusive) окна не перекрываются в принципе — работает только для borderless/оконных полноэкранных режимов.

## 9. Автообновление (v0.1, R1 / F1)

- Эндпоинт: `https://github.com/sshyngys1/ccott/releases/latest/download/latest.json` (`tauri-plugin-updater`, публичный ключ minisign в `tauri.conf.json`, режим установки Windows — `passive`).
- Тип `UpdateInfo { version: string; notes: string; date: string | null }`.
- R1 проверяет обновления через ~30 с после старта и затем каждые 6 ч. При отсутствии сети или релиза (404 / `ReleaseNotFound`) — тихо, только `log::info`, без ошибки для UI.
- При обнаружении новой версии R1 кэширует пакет обновления и эмитит `updater://available` (`UpdateInfo`).
- `updater_check` (`{}` → `UpdateInfo | null`) — ручная проверка из настроек (при отсутствии сети или 404 также возвращает `null` без ошибки).
- `updater_install` (`{}` → `void`) — скачивает установщик, проверяет подпись minisign, запускает NSIS в режиме `passive` и перезапускает приложение.
- F1 показывает в настройках текущую версию, кнопку «Проверить обновления», при наличии новой версии — строку «Доступна версия X» с кнопкой «Установить и перезапустить», а также одноразовый тост в пилюле «Доступно обновление» (с учётом `doNotDisturb`).

## 10. Язык интерфейса (v0.2)

- `Settings.language: "auto" | "ru" | "en"`, по умолчанию `"auto"`. `"auto"` = язык интерфейса Windows: русский → `"ru"`, любой другой → `"en"`.
- UI: словари `src/i18n/{ru,en}.ts` (тип ключей выводится из `ru`, `en` обязан содержать все ключи — проверяет TypeScript), хук `useT()` и `t(key, params?)` без сторонних зависимостей; язык меняется на лету по `settings://changed`, без перезапуска. `<html lang>` следует за языком. Модулям (`src/modules/*`) — тот же `useT()`.
- Rust (R1): трей и прочие нативные строки локализуются по `Settings.language` (для `"auto"` — `GetUserDefaultUILanguage`), обновляются при `settings://changed`.
- Данные пользователя (заметки, буфер, имена устройств, треки) не переводятся. Текстовые утилиты RU⇄EN (раскладка, транслит) от языка UI не зависят.

## 11. Захват экрана и OCR (v0.2)

- `capture_start({ mode: "region" | "screen", action: "copy" | "save" | "ocr" })` → `CaptureResult | null`. `null` — пользователь отменил (Esc / правый клик). Ошибка — строка для пользователя (например, «нет языкового пакета OCR»).
- На время захвата остров скрывается (без анимации) и возвращается после. Курсор и сам остров в снимок не попадают.
- `region`: снимок всех мониторов замораживается, поверх — полноэкранный оверлей (затемнение, рамка выделения, размер в пикселях, лупа не обязательна). Тянуть мышью — выделить, отпустить — готово, Esc / правый клик — отмена. Корректно на нескольких мониторах с разным DPI (физические пиксели).
- `screen`: монитор под курсором целиком.
- `copy`: PNG в буфер обмена (CF_DIB/PNG), он же попадает в историю буфера обычным путём. `save`: PNG в `Pictures\Screenshots\CCOTT\CCOTT YYYY-MM-DD HH-MM-SS.png` + в буфер. `ocr`: `Windows.Media.Ocr` (офлайн), язык — из языков профиля пользователя (ru и en, если установлены); текст в буфер.
- UI после результата показывает тост в пилюле: «Скопировано» / «Сохранено» (клик — `capture_open_folder`) / «Текст скопирован» или «Текст не найден».
- `capture_open_folder` открывает папку снимков в Проводнике.

- v0.2.1: `Settings.ocrLanguage` — `"auto"` (как раньше, языки профиля Windows) или тег языка из `capture_ocr_languages` (`OcrLanguage { tag, name }`, установленные в Windows языки OCR). Выбранный язык используется для «Текст с экрана»; если он пропал из системы — откат на `"auto"` с записью в лог. В настройках — выпадающий список «Язык распознавания текста» и подсказка, как добавить язык (Параметры Windows → Время и язык → Язык → добавить язык с компонентом «Оптическое распознавание символов»).

## 12. Пипетка и QR (v0.2)

- `capture_pick_color({})` → `PickedColor { hex: "#RRGGBB", r, g, b } | null`. Тот же замороженный оверлей, что и у захвата, но с лупой (увеличение пикселей вокруг курсора, сетка, текущий HEX рядом). Клик — выбрать, Esc / правый клик — отмена. HEX копируется в буфер; UI показывает тост с образцом цвета и HEX.
- QR-распознавание: `capture_start({ mode: "region", action: "qr" })` — выделенная область декодируется (Rust), `CaptureResult.text` = содержимое QR ("" если не найден), содержимое в буфер. Если это ссылка http(s) — тост с кнопкой «Открыть» (открытие в браузере по умолчанию, только http/https).
- QR-создание — чисто во фронтенде: во вкладке «Текст» действие «QR-код» показывает QR для текущего текста (или выделения) с кнопкой «Копировать как картинку» (PNG в буфер через `navigator.clipboard` или существующий путь).

## 13. Док (v0.2)

- `DockItem { id, path, name, kind: "app" | "folder" | "file", icon }`; хранение — SQLite (R2), порядок = порядок отображения, максимум 12 элементов, дубликаты по пути игнорируются.
- `dock_list`, `dock_add({ paths })`, `dock_remove({ id })`, `dock_reorder({ ids })` возвращают новый список и эмитят `dock://changed`. `dock_open({ id })` — действие оболочки по умолчанию (ShellExecute), для пропавшего пути — ошибка для пользователя («Файл не найден»), элемент не удаляется сам.
- Имя: у `.lnk`/`.url` — имя ярлыка, у `.exe` — FileDescription из версии, иначе имя файла без расширения; у папки — её имя. Иконка — системная (как в Проводнике), 64×64 PNG data URL, кэшируется.
- Добавление: перетаскивание файлов/папок/ярлыков из Проводника, с рабочего стола или из меню «Пуск» на остров (в свёрнутом виде остров раскрывается на Главной) или кнопкой «+» (системный диалог выбора). Удаление — контекстное меню / кнопка при наведении. Перестановка — перетаскиванием внутри дока.

## 14. Автоскрытие над приложениями и Esc после вызова (v0.2)

- `Settings.autoHideApps: string[]` — exe в нижнем регистре. По умолчанию: `chrome.exe`, `msedge.exe`, `firefox.exe`, `browser.exe` (Яндекс), `opera.exe`, `brave.exe`, `vivaldi.exe`. Старый settings.json без поля получает этот список.
- Пилюля скрывается, пока активное окно принадлежит приложению из списка и развёрнуто (maximized) или его верхний край касается верха монитора острова. Не путать с полноэкранным режимом (§8): там своя логика.
- Показ: горячая клавиша вызова (как сейчас) или удержание курсора у верхнего края в зоне пилюли ~400 мс — пилюля выезжает и ведёт себя как обычно (hover раскрывает). После ухода курсора и сворачивания снова скрывается. Live-activities в это время не показываются.
- Настройки (F1): список как у полноэкранных приложений — недавно активные развёрнутые приложения с переключателями «Прятать остров» + добавить exe вручную + удалить; кнопка «Сбросить к браузерам».
- Esc после вызова горячей клавишей: пока остров раскрыт вызовом (`island://summoned`) и не получил клавиатурный фокус, R1 временно регистрирует глобальную клавишу Esc → сворачивание; снимает её при сворачивании. Фокус у активного окна не забирается (безопасно для игр). Когда остров имеет клавиатурный фокус — работает обычный Esc из §3a.
- `window_recent_maximized_apps` (`{}` → `FullscreenApp[]`) — недавно виденные развёрнутые активные приложения (R1 хранит до 20 в `maximized_seen.json`) для списка автоскрытия в настройках.
- Док (§13): `dock_start_drag({ id })` — нативное перетаскивание файла/папки элемента наружу (копирование, OLE CF_HDROP); ошибка «Файл не найден», если путя больше нет. UI вызывает его, когда указатель при перетаскивании ярлыка выходит за пределы дока.

## 15. Прогрев перед раскрытием и стартовая вкладка (v0.2.1)

- Событие `island://prewarm` (R1 → UI, без данных): курсор приближается к свёрнутой пилюле или нажата горячая клавиша вызова. UI делает один дешёвый невидимый кадр, чтобы «разбудить» композитор WebView2 до начала раскрытия. R1 троттлит событие (не чаще ~раза в 500 мс) и не шлёт его, пока курсор далеко, — в простое 0% CPU.
- Каждое раскрытие острова открывает вкладку «Главная». Исключения: «Настройки» из трея, перетаскивание файла (Главная с доком), действия тостов, ведущие в конкретное место.

## 16. Батарея и реальный аудиоиндикатор (v0.2.2)

Контракт добавлен Orchestrator до запуска следующего исполнителя. Владелец реализации — agy; существующие MediaState/Settings не меняются.

- `system_get_battery({})` → `BatteryState`; `system://battery` → тот же снимок при изменениях. Поля: `hasBattery: boolean | null`, `percent: number | null` (0..100), `charging: boolean | null`, `acConnected: boolean | null`, `saver: boolean | null`, `remainingSeconds: number | null`. `null` означает неизвестное значение, а не ноль/false. При отсутствии батареи `hasBattery=false`, процент/зарядка/оставшееся время — null; питание от сети может быть известно. Ошибка Win32 не прекращает запуск приложения. Источник — GetSystemPowerStatus; unknown sentinels не превращаются в 255% или ложное «батареи нет». Опрос порядка 5 секунд / уведомления питания; события только при изменениях. UI скрывает батарею при false/null, сохраняет 0%, не вытесняет медиапилюлю.
- `audio_visualizer_set_enabled({ enabled: boolean })` → void — идемпотентный запрос потребителя. Один фронтенд-сервис последовательно согласует enable/disable и cleanup StrictMode/HMR; true запрашивается только при воспроизведении и наличии показанного Eq. Даже при true нативный worker приостанавливает захват, пока окно island скрыто. Без потребителя захват остановлен. Нельзя менять настройки громкости, устройства, микрофона или воспроизведения ради визуализации.
- `audio://spectrum` → `AudioSpectrum { available: boolean, bands: [number,number,number,number], sampledAt: number }`. bands — четыре возрастающих диапазона частот, измеренные из PCM default render endpoint (WASAPI loopback), конечные значения 0..1, тишина — нули. sampledAt — epoch ms. До 20 событий/сек при активном видимом индикаторе; unavailable/stop/error очищает уровни. В UI кадр старше 500 мс сбрасывается в спокойное состояние. Никаких случайных значений или циклической анимации вместо измерений.
- Это системный выход выбранного Windows устройства, не микрофон и не изолированный аудиопоток YouTube Music. PCM остаётся только в ограниченных оперативных буферах Rust: не сохранять, не отправлять в сеть/UI/логи. После mute/volume=0, pause, ошибки/смены/потери устройства и скрытия индикатор успокаивается, при возобновлении сам восстанавливается. Захват/COM/буферы освобождаются корректно, отсутствие устройства не ломает приложение.
- Мок поддерживает новые команды/события и явную инъекцию battery/spectrum для тестов, без выдачи синтетического цикла за настоящий звук.

## 18. Настройка плиток быстрых инструментов (v0.3)

- `Settings.quickTiles: TileSlot[]` — упорядоченная раскладка плиток на «Главной». `TileSlot { id: TileId, size: TileSize }`; `TileId = "region" | "screen" | "ocr" | "qr" | "color"`; `TileSize = "1x1" | "2x1"` (ячейка или целая строка двухколоночной сетки).
- Сетка 2 колонки × 3 строки: сумма ячеек ≤ `QUICK_TILE_CELLS` (6; `"2x1"` = 2). id уникальны. `[]` допустим (все плитки скрыты — UI показывает подсказку «добавить»).
- **Этап 2 (v0.3):** `QUICK_TILE_CELLS = 8`. При сумме ячеек > `QUICK_TILE_ROW_CELLS_3` (6) сетка получает 4-ю строку, и раскрытая панель становится выше ровно на одну строку плиток + gap (высокий размер панели); при ≤ 6 — прежний размер 720×396. Высокая панель целиком (с тенью) помещается в окно `ISLAND_WINDOW` (800×520) — окно не меняется. Размер берётся из настроек при раскрытии; hover/shape-зоны (`island_set_shape`), прогрев и анимация раскрытия используют фактический размер. Rust отклоняет раскладку с суммой ячеек > 8.
- Новые `TileId` (ярлыки на уже существующие функции, без новых команд): `screenshots` — открыть папку снимков (`capture_open_folder`); `note` — вкладка «Заметки» с новой заметкой; `timer` — вкладка «Заметки», раздел таймера; `clipboard` — вкладка «Буфер». Размеры 1×1 и 2×1. В умолчание не входят — добавляются через «+».
- По умолчанию `DEFAULT_QUICK_TILES` (= раскладка v0.2.x): region, screen, ocr, qr — 1×1, color — 2×1. Rust-умолчание идентично; старый settings.json без поля получает его.
- Rust (`settings_set`) отклоняет поле целиком (в списке rejected), если: не массив, элемент не `{id: string, size: "1x1"|"2x1"}`, дубликаты id, сумма ячеек > 6, id длиннее 32 символов. Неизвестный, но корректный по форме id Rust сохраняет (совместимость с более новой сборкой); UI неизвестные id пропускает и не считает в ячейки.
- Новых команд нет: сохранение — `settings_set({ quickTiles })`, сброс — `settings_set({ quickTiles: DEFAULT_QUICK_TILES })`; изменения приходят через `settings://changed`.
- Реестр плиток (иконка, ключ i18n, действие, допустимые размеры) — во фронтенде (`src/lib/tiles`); добавление новой плитки = расширение `TileId` (правка контракта Orchestrator).

## 19. Режим «Лёгкий» (v0.3)

- `Settings.liteMode: boolean`, по умолчанию `false`; старый settings.json без поля получает `false`; не-boolean → поле в rejected.
- Включён: UI ставит на `<html>` атрибут `data-lite="true"` (как `data-vibrancy`), и CSS заменяет эффекты стекла плоскими непрозрачными поверхностями из токенов: без specular-кромки (`::before`), зерна (`::after`), подсветки под курсором, `backdrop-filter`/преломления, многослойных теней (остаётся тонкая обводка). Обе темы; контраст текста не хуже обычного режима.
- Анимации раскрытия, fx (переворот обложки, волна дока) и индикатор звука не отключаются. Нативный vibrancy (acrylic/mica) при liteMode не применяется окну (поверхность плоская).
- Переключатель — в настройках («Оформление»), применяется сразу через `settings_set` / `settings://changed`, без перезапуска.

## 20. Командная строка (v0.3)

Дизайн — `docs/design-spec.md`, раздел «Командная строка» (одобрен пользователем 2026-11-02), стенд `src/design/preview` (`solo=cmd`).

- `Settings.commandHotkey: string` — глобальный хоткей (синтаксис Tauri), по умолчанию `"Ctrl+Alt+Space"`, `""` = выключен; конфликт/ошибка регистрации — как у `summonHotkey` (сообщение в UI, прежнее значение). Нажатие: остров показывается (и над полноэкранными, как summon), берёт фокус клавиатуры, Rust шлёт `cmd://open`; повторное нажатие / Esc на пустом поле закрывают.
- `cmd_search({ query, limit })` → `CmdItem[]` (приложения и файлы, лучшие сначала). Источники: ярлыки «Пуска» (`%ProgramData%` и `%AppData%\Microsoft\Windows\Start Menu\Programs`, .lnk/.url) + приложения Store (shell:AppsFolder); файлы и папки — Windows Search (SystemIndex) по профилю пользователя, если индекс недоступен — ограниченный обход Desktop/Documents/Downloads/Pictures. Индекс строится в фоне, первый запрос не ждёт его готовности. Нечёткое совпадение по началу слов/подстроке, без учёта регистра и раскладки не требуется. Без логирования запросов пользователя.
- `CmdItem { id, kind: "app"|"file"|"folder", title, subtitle, icon }` — `icon` — PNG data URL настоящей иконки (≤ 64 px) или null (UI рисует по типу).
- `cmd_launch({ id, mode })`: `open` — действие по умолчанию; `admin` — запуск с повышением (только app; отказ UAC → тихо); `reveal` — показать в Проводнике. После запуска UI сворачивает остров и отдаёт фокус.
- `cmd_currency_rates({ base })` → `CurrencyRates { base, rates, updatedAt, stale }`. Провайдер без ключа (например open.er-api.com, атрибуция в «О программе»), только HTTPS, в запросе — только код базовой валюты. Кэш на диске (в каталоге данных приложения) ≤ 12 ч свежий; при сетевой ошибке — кэш со `stale: true`; ни сети, ни кэша — reject.
- Калькулятор, проценты, единицы и команды («таймер 10 мин» → существующий таймер) — чистая логика во фронтенде (`src/lib/cmd`), без IPC. Строки — RU/EN.
- Мок поддерживает все три команды и событие (фиксированные данные, без сети).

### 20a. Занятые сочетания и плитка «Командная строка» (v0.3)

Причина: у многих стоит приложение Claude, его быстрый ввод занимает `Ctrl+Alt+Space`; раньше CCOTT молча оставался без хоткея, а настройки показывали неработающее сочетание.
- `HotkeyStatus { summon, command: "ok"|"busy"|"off", commandFallbackFrom }`; команда `hotkeys_status({})`, событие `hotkeys://status` (при старте, после каждой смены настроек хоткеев, после запасного варианта).
- Запасной вариант (R1, только при старте и только если `commandHotkey` равен умолчанию `"Ctrl+Alt+Space"`): если занят — по порядку `COMMAND_HOTKEY_FALLBACKS`; первое свободное регистрируется и **сохраняется** в `settings.json` (`settings://changed`), `commandFallbackFrom = "Ctrl+Alt+Space"`. Ничего не свободно → `command: "busy"`, значение не меняется. Пользовательское (не умолчание) сочетание не подменяется — только `busy`.
- UI: в настройках у строк «Вызов острова» и «Командная строка» при `busy` — пометка «Занято другим приложением — выберите другое» (danger-токен); при `commandFallbackFrom` — один раз тост на пилюле «Ctrl+Alt+Space занято — командная строка: Ctrl+Shift+Space» (с кнопкой «Настройки»), повторно не показывать для того же значения. Отклонённая при записи комбинация показывает понятную ошибку и не сохраняется (как сейчас), поле возвращается к прежнему значению.
- Плитка `TileId "command"` («Командная строка», 1×1/2×1): открывает командную строку мышью — `setView("cmd")` + раскрытие без ожидания курсора (так же держится до Esc/клика в другое окно). В `DEFAULT_QUICK_TILES` не добавляется; доступна в «Добавить плитку».
- Мок: `hotkeys_status` → всё `ok`; помощник для тестов, имитирующий `busy`/fallback.

## 22. Полка файлов (v0.3)

Полка — временное место для файлов «на минутку» (в отличие от дока — постоянных ярлыков).
- **Положить:** перетащить файлы/папки из Проводника или браузера на **свёрнутую пилюлю** (пилюля подсвечивается, подпись «Бросьте на полку») или на вкладку «Полка». Бросок в зону дока раскрытой «Главной» по-прежнему идёт в док. Файлы НЕ копируются — хранится путь.
- **Вкладка `ModuleId "shelf"`** (`src/modules/shelf`): сетка значков (имя, размер), выделение нескольких (Ctrl/Shift), перетаскивание выделенного наружу (`shelf_start_drag`), меню: «Открыть», «Показать в папке», «Убрать с полки»; кнопка «Очистить полку». Пустая — подсказка «Перетащите файлы на остров». Отсутствующий файл — серый, с пометкой «Файл перемещён или удалён», только «Убрать».
- **Пилюля:** пока полка не пуста — маленький значок полки с числом файлов (не вытесняет медиа/загрузки; приоритет ниже них).
- **Настройки** (раздел «Полка»): `shelfKeepAfterDrag` — «Оставлять файл на полке после перетаскивания» (умолчание выкл.: вытащенный файл уходит с полки); `shelfRetentionHours` — «Хранить на полке»: 1 ч / 24 ч / 3 дня / 7 дней / Бессрочно (`SHELF_RETENTION_HOURS`, 0 = бессрочно; умолчание 24 ч).
- **R2 (`src-tauri/src/shelf`):** список в SQLite (`db`), id стабильные; истечение проверяется при старте, в `shelf_list` и таймером ≤ раз в 10 мин; `missing` пересчитывается при `shelf_list`/показе вкладки. Иконки — как у дока (≤ 64 px PNG). Drag-out — нативный (OLE DoDragDrop, как `dock_start_drag`), несколько файлов разом; удаление с полки — только при успешном броске и `shelfKeepAfterDrag = false`. Событие `shelf://changed` на каждое изменение. Пути и имена не логируются.
- Мок: все команды, событие, примеры файлов (в т. ч. один `missing`).
- **v0.4 — выбор «Док или Полка» при броске на свёрнутую пилюлю** (решение пользователя 2026-11-03): когда перетаскиваемые файлы входят в зону свёрнутой пилюли и включены **обе** функции (`dock`, `shelf` не в `disabledFeatures`), остров раскрывается и вместо обычного содержимого показывает две крупные зоны броска «В док» и «На полку» (иконка + подпись, подсветка зоны под курсором). Бросок в зону — туда; уход курсора с острова без броска / Esc — остров сворачивается, ничего не добавлено. Включена только одна из функций — без выбора, сразу туда (как в §23). Бросок в док по-прежнему только для того, что док принимает (приложения/папки/файлы — как сейчас); неподходящее для дока — зона «В док» показана неактивной с подсказкой. На раскрытом острове поведение прежнее (зона дока на Главной / вкладка «Полка»). Новых команд нет: `dock_*` и `shelf_add` как сейчас. Строки RU/EN.

## 21. Монитор загрузок (v0.3)

- `Settings.downloadsMonitor: boolean`, по умолчанию `true`; выключено — R2 не следит за папкой (watcher остановлен, ничего не держит в памяти).
- Папка — «Загрузки» пользователя (known folder `FOLDERID_Downloads`, учитывая перенос пользователем). Слежение — уведомления файловой системы (ReadDirectoryChangesW / notify), без опроса диска чаще 1 раза в секунду.
- Активная загрузка: частичный файл браузера `.crdownload` (Chrome/Edge/Яндекс/Opera/Brave), `.part` (Firefox), `.download` — пока он растёт. `name` — итоговое имя без суффикса (у Chrome временное имя `Не подтверждено 123.crdownload` / `Unconfirmed 123.crdownload` → имя берётся после переименования; до этого — нейтральное «Загрузка…» в UI, поле `name` = "" ).
- `done`: частичный файл переименован в итоговый (тот же `id`); `failed`: частичный файл удалён без итогового или не растёт > 60 с и браузер его удалил. Новый обычный файл без частичного (Edge/Firefox иногда пишут сразу) — сразу `done`, без прогресса.
- `totalBytes` обычно `null` (браузеры не сообщают размер в файле) — UI показывает размер и скорость без процентов; если известен — проценты/кольцо.
- `downloads_list({})`, `downloads_open({ id, mode: "open" | "reveal" })`, событие `downloads://changed` (≤ 2 Гц пока идут байты, сразу при смене state). Готовые/ошибочные держатся в списке 5 минут.
- UI: пока есть active — живая активность в пилюле (иконка загрузки, имя, «12,4 МБ · 3,1 МБ/с»; при нескольких — «3 загрузки»), приоритет выше медиа-пилюли; по завершении — тост «Скачано: имя» с действиями «Открыть» / «Показать в папке» (одним нажатием, без разворота острова). Строки RU/EN. Ничего не отправляется в сеть, имена файлов не логируются.

## 23. Отключаемые функции и порядок вкладок (v0.4)

- `Settings.disabledFeatures: FeatureId[]`, по умолчанию `[]`. `FeatureId = "clipboard" | "text" | "notes" | "shelf" | "dock" | "battery" | "audioMeter"`. Главная (`home`) не отключается. Загрузки остаются на своём `downloadsMonitor` (в UI — в том же списке функций).
- Выключенная функция не показывается и **не держит память и фоновые задачи**:
  - `clipboard` — вкладка скрыта, R2 останавливает слежение за буфером (как `downloads::set_enabled`); сохранённая история не удаляется, командная строка её не показывает.
  - `text`, `notes`, `shelf` — вкладка скрыта, её код не загружается; у `notes` таймер/заметки не тикают в пилюле; у `shelf` бросок на свёрнутую пилюлю не принимается (а при включённом доке идёт в док), значок полки в пилюле скрыт.
  - `dock` — док на Главной скрыт, бросок в его зону не принимается.
  - `battery` — индикатор и опрос заряда выключены. `audioMeter` — индикатор звука выключен, захват WASAPI не запускается.
- `Settings.tabOrder: ModuleId[]`, по умолчанию `DEFAULT_TAB_ORDER` (`home, clipboard, text, notes, shelf`). UI берёт порядок отсюда; недостающие известные id дописывает в конец по `DEFAULT_TAB_ORDER`; неизвестные пропускает. Главную можно переставить, но не скрыть.
- Режим правки вкладок (как у плиток §18): правый клик по полосе вкладок → «Изменить вкладки»; вкладки перетаскиваются, у каждой (кроме Главной) «×» = выключить функцию; «+» показывает выключенные вкладки, выбор включает; «Сбросить» = `tabOrder: DEFAULT_TAB_ORDER` и включение всех вкладочных функций; «Готово»/Esc — выход. Если видна одна вкладка — полоса вкладок не рисуется.
- Rust (`settings_set`): `tabOrder` / `disabledFeatures` — массив строк ≤ 16 элементов, каждая 1–32 символа, без дубликатов, иначе поле в rejected; `"home"` в `disabledFeatures` отбрасывается. Неизвестные корректные по форме id сохраняются (совместимость с новой сборкой). Старый settings.json без полей получает умолчания.

## 24. Валюта по умолчанию и автодополнение валют (v0.4)

- `Settings.defaultCurrency: string` — код ISO 4217 в верхнем регистре или `""` (умолчание: как раньше). Rust: `""` или ровно 3 латинские буквы (приводит к верхнему регистру), иначе rejected.
- Командная строка: если запрос — сумма с валютой без целевой («100 usd»), переводит в `defaultCurrency` (если задана и отличается от исходной).
- Автодополнение: после « в » / « to » (и при вводе кода валюты) — список валют, сужающийся по первым буквам кода и названию (RU/EN); лучший вариант выбран по умолчанию, Tab/Enter подставляет, стрелки — выбор. Список — валюты, которые знает источник курсов. Без сети — по кешу.
- Настройки: «Валюта по умолчанию» — выпадающий список с поиском, первый пункт «Не задана».

## 25. Окно настроек (v0.4)

- Настройки — **отдельное обычное окно Windows** (label `settings`, страница `settings.html`), а не экран внутри острова: заголовок с кнопками окна, значок на панели задач, активируется и получает клавиатуру как обычное окно, размер ~760×680 (мин. 640×520), по центру монитора острова, тема/язык/«Лёгкий» — как у острова.
- `settings_window_open({})` → `null` (R1): создаёт окно, если его нет, иначе показывает и фокусирует (одно окно на все вызовы). Закрытие уничтожает окно (WebView не держится в памяти).
- Кто открывает: шестерёнка в острове (`settings_window_open`; остров при этом сворачивается), пункт трея «Настройки» (R1 открывает окно напрямую). Событие `island://open-settings` больше не используется UI (оставлено в реестре для совместимости).
- Окно работает с теми же командами `settings_*`, `window_*`, `updater_*`, `capture_ocr_languages` и т. п.; изменения применяются сразу и приходят в остров через `settings://changed`. Capabilities окна — только нужные ему команды.

## 26. Погода (v0.4, волна 3)

- Источник — **Open-Meteo** (без ключа): прогноз `current` + `hourly` (24 ч) + `daily` (7 дней) + `minutely_15` (осадки на 2 ч → `precipInMin`/`precipKind`) и геокодинг `geocoding-api.open-meteo.com` (язык ru/en). Все запросы — из Rust (R2, `src-tauri/src/weather`), с понятным User-Agent `CCOTT/<версия>`; кеш отчёта на диске рядом с settings.json; обновление не чаще раза в 30 мин и только пока функция `weather` включена (выключена — ни таймеров, ни запросов). Без сети — кеш со `stale: true`.
- `Settings.weatherLocation: WeatherLocation | null` (умолч. `null`), `Settings.weatherUnits: "c" | "f"` (умолч. `"c"`). Rust валидирует: lat −90…90, lon −180…180, name 1–120 символов; units — только `"c"`/`"f"`.
- Место: поиск города (`weather_search_location`) или «Определить автоматически» (`weather_locate`, Windows Geolocation — Windows сам спрашивает разрешение; отказ → понятное сообщение, ручной поиск остаётся). Координаты никуда, кроме Open-Meteo, не отправляются и не логируются.
- UI: вкладка `ModuleId "weather"` — сейчас (иконка, температура, ощущается, ветер, влажность), строка по часам (24 ч, горизонтальная прокрутка), 7 дней (мин/макс). Пока место не выбрано — экран выбора места. Живая активность в пилюле: «Через 20 мин дождь» (если `precipInMin` ≤ 30 и функция включена), приоритет ниже загрузок и медиа. Иконки погоды — свои, в стиле `src/design/icons.tsx`. Настройки: раздел «Погода» (место, единицы).

## 27. Центр управления (v0.4, волна 3)

- Вкладка `ModuleId "control"`: плитки Wi-Fi и Bluetooth (вкл/выкл одним нажатием, подпись — сеть/«Выключен»/«Недоступно»), «Тёмная тема Windows» (вкл/выкл), «Режим питания» (Экономия / Сбалансированный / Производительность), список сопряжённых BT-устройств с зарядом (если устройство сообщает), ссылки «Открыть параметры Windows» (`control_open_settings`).
- R2 (`src-tauri/src/system` или новый `control`): радио — WinRT `Windows.Devices.Radios` (`Radio.RequestAccessAsync`, `SetStateAsync`), без прав администратора; если драйвер/политика не дают — `state: "unavailable"` и отказ `control_set_radio` с сообщением. Wi-Fi SSID/сигнал — `WlanApi`. Тема — `HKCU\…\Themes\Personalize` `AppsUseLightTheme`/`SystemUsesLightTheme` + рассылка `WM_SETTINGCHANGE "ImmersiveColorSet"`. Режим питания — `PowerGetEffectiveOverlayScheme`/`PowerSetActiveOverlayScheme` (если API нет — `powerMode: null`, плитка скрыта). Заряд BT — свойство устройства `DEVPKEY_Bluetooth_Battery` / Battery Service там, где есть.
- `control://changed` — при изменениях (в т. ч. снаружи CCOTT); слежение только пока функция `control` включена и вкладка/плитки кому-то нужны; без опроса чаще раза в 5 с.
- Плитки Главной `wifi` и `bluetooth` (новые `TileId` — добавит Orchestrator при приёмке, если понадобятся; в этой волне — только вкладка).

## 28. Напоминания (v0.4, волна 3; функция `notes`)

- Хранение — R2 в SQLite (`db`), команды `reminders_*`, события `reminders://changed`, `reminders://due`. Rust держит один таймер до ближайшего `dueAt` (не опрос); при старте выдаёт `due` для пропущенных, пока приложение было закрыто (одним списком, без спама).
- Ввод на естественном языке (RU/EN) в UI: «напомни через 20 минут позвонить маме», «завтра в 9 встреча», «в пятницу в 18:00 …», «remind me in 2 hours to …». Парсер — чистый TS в `src/lib/reminders` с тестами (можно `chrono-node`, если покрывает RU — тогда указать в отчёте для установки; иначе свой). Доступно из командной строки («напомни …» / «remind …» → предпросмотр «Напомню в 18:00: …», Enter создаёт) и в вкладке «Заметки» (раздел «Напоминания»: список, отметка, удаление).
- Срабатывание: тост в пилюле с текстом и действиями «Готово» / «Отложить на 10 мин», звук как у таймера; при «Не беспокоить» — без звука, тост остаётся. Выключена `notes` — таймер напоминаний снят, после включения пропущенные выдаются.

## 29. Монитор ИИ-агентов (v0.4, волна 3)

- Идея: Claude Code и Codex CLI сообщают острову о состоянии сессий; в пилюле — «Claude ждёт ответа» / «Codex закончил» (имя проекта), тост при `waiting`/`done`, список сессий — **отдельная вкладка `ModuleId "agents"`** (решение пользователя 2026-11-09; до этого был раздел во вкладке «Управление»), скрывается функцией `agents` и режимом правки вкладок. Приоритет в пилюле: `waiting` выше медиа (важно), `working` — только значок.
- Канал: локальный, без сети — именованный канал `\.\pipe\ccott-agents` (R2 сервер). Хук-команда записывает в канал одну JSON-строку `{tool, event, sessionId, cwd, message?}`; если CCOTT не запущен — молча выходит за < 100 мс и **никогда не блокирует и не ломает** работу агента (exit 0, без вывода). Способ отправки (маленький исполняемый помощник рядом с CCOTT или PowerShell-однострочник) — на выбор исполнителя, с обоснованием.
- Claude Code: хуки в `%USERPROFILE%\.claude\settings.json` — `UserPromptSubmit`/`PreToolUse` → working, `Notification` → waiting (текст уведомления), `Stop` → done. Codex: `notify` в `%USERPROFILE%\.codex\config.toml` (turn-complete → done). `agents_set_hooks` добавляет/убирает только свои записи (помечены, распознаются по команде), сохраняет остальные, делает резервную копию файла перед изменением, не трогает файл, если не может его разобрать. Включается только по явной кнопке пользователя в настройках (раздел «Агенты») с пояснением, что будет изменено.
- Сессия без событий 30 мин → удаляется; `done` держится 10 мин. В UI — только имя папки проекта, без полных путей и без содержимого переписки.

## 30. Текст песен (v0.4)

Дизайн — `docs/design-spec.md` §6.11 (утверждён пользователем 2026-11-09; превью `src/design/preview/lyrics.html`). Отличие от предложения дизайна: **поиск текста включён по умолчанию** (`Settings.lyrics.enabled = true`, решение пользователя).
- `Settings.lyrics: LyricsSettings` — `{ enabled: true, inPill: true, announce: false, offsetMs: 0 }`; Rust валидирует `offsetMs` −5000…5000 (целое), остальные — boolean; старый settings.json без поля получает умолчания. `FeatureId "lyrics"` — выключенная функция: нет кнопки «Текст», вида, строки в пилюле, запросов и окраски острова.
- `lyrics_get({ title, artist, album, durationMs, force? }) → LyricsResult` (R2; `force` — кнопка «Повторить»: забыть кеш и 10-минутный лимит для трека): LRCLIB: нормализация названия/исполнителя (убрать feat./Remastered/Explicit…, первый исполнитель), цепочка `get` → `get` без альбома → `get` с исходным названием → `search` по полям → `search?q=`; выбор по длительности ±3 с и нестрогому совпадению, synced предпочтительнее; User-Agent `CCOTT/<версия> (+https://github.com/sshyngys1/ccott)`; таймаут 5 с; разбор LRC (несколько меток на строку, `[offset:]`), сортировка; кеш в SQLite (найденное, `notFound` и `instrumental`; TTL «не найдено» 1 день — решение 2026-11-09 после живой проверки); не чаще одного сетевого запроса на трек в 10 мин. Никогда не отклоняет — ошибки как `{ status: "error" }`. При `enabled = false` — `notFound` без сети. Названия треков не логируются.
- UI (F1/F2) — по §6.11 п.11: стор `src/lib/lyrics` (дебаунс 300 мс при смене трека, активная строка от экстраполированной позиции + `offsetMs`), кнопка на карточке плеера, вид «Текст песни» (как отдельный экран острова, Esc — назад), строка в пилюле (ширина `pillLyrics`, приоритет как у медиа-пилюли, которую она заменяет), окраска острова под обложку (`paletteFromImage`), «Лёгкий»/reduced motion. Настройки: раздел «Текст песен» (поиск в интернете, в пилюле, озвучивание, сдвиг) и переключатель функции в «Функциях».
- **Мок и тесты — только выдуманные строки текста.** Тексты реальных песен никогда не попадают в репозиторий, тесты, логи или скриншоты.
